# Work log — 2026-09-26 (UdiFy)

Plain-language summary of the day. Written 2026-09-27 as a backfill — the
work was done and committed, but never written up at the time.

## What I set out to do

Clear the remaining items blocking the release approval, then start
checking the app against the *real* government portals.

## What I did

**Cleared release blockers.** Added a way for the app to save its progress
while it works, so if something goes wrong halfway it can pick up where it
left off instead of starting over or — worse — creating a duplicate entry
on a government portal. Also added a guard that checks "did I already try
this?" before clicking any one-shot "create new student" button.

**Checked the app on the real school computer.** Turned out this computer
*is* the computer the school uses for UDISE work, so there was no separate
test machine to worry about. Ran the app for real, clicked the buttons,
watched a real browser window open, and screenshotted the whole run.

**Made the settings screen editable.** Previously you had to open a text file
by hand to enter passwords and spreadsheet IDs. Now the app has a proper
Settings screen with fields and a Save button.

**Set up Google access.** Created a dedicated service account for the app
(your existing Google Play one was left completely alone), turned on the
required API, and shared the three real spreadsheets — OGR, UDISE, and PEN —
with it.

**Made the settings screen look right.** Fixed three genuine display bugs I
found while looking at it: every text label had a stray grey box behind it,
the service-account row got garbled when the window was maximized, and the
greyed-out hint text got cut off.

**Hit a Windows security wall on the packaged .exe.** Windows' Smart App
Control blocks the app because a PyInstaller build isn't digitally signed.
I did **not** touch that setting — turning it off is permanent and it's your
decision, not mine. Instead I set up a Start Menu shortcut that launches the
app normally, which works today. Also built a proper Windows installer.

**Found 6 real bugs in the portal automation** by actually logging into both
government portals. Every one was something no amount of guessing would have
found — for example, the submit button on the national portal says "Sign In",
not "Login", and the password boxes couldn't be found by their labels. All
six are fixed.

## Decisions

- Turned on "live mode" at your instruction, so the app can be tested
  against the real portals.
- Left Windows Smart App Control completely alone — that's your call.
- Used Inno Setup for the installer, with your OK first, since it installs
  software on the machine.

## Where things stand

Login to both government portals and reading the real spreadsheets both
work. The rest of the live checking hasn't started.
