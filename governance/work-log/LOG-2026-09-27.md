## Even later — full review, and a serious problem it uncovered

You asked me to review the whole project. I found something important and
bad, so I want to be completely straight about it.

**The app was never actually able to talk to the real websites.**

When I checked, I found that although the app was correctly set to
"live mode" and correctly connected to your real spreadsheets, every screen
inside the app was still opening the **fake test pages** stored on this
computer. It would open a local file pretending to be the government
website, "log in" to it with a made-up password, and then write that fake
result into your **real** spreadsheet.

It would have *looked* like it worked. That's the dangerous part — you could
have ended up with rows in your real registers that were never really
processed by any government portal.

**Why nobody caught it earlier:** all 110 tests tested the fake version,
because that's the part that had been built. The real-website code path had
never been tested at all, so it couldn't fail. The earlier check-ins today
about "live but unverified" and about the settings keeping things safe were
both wrong, and I've corrected them in the project records rather than
quietly moving on.

**What I fixed**

- Built one single place that decides "real website or test pages", based on
  your settings. Every screen now uses it, so no screen can get it wrong on
  its own.
- If live mode is switched on but something's missing (a password, an
  address), it now **stops with a clear message** instead of quietly using
  the fake pages. That fallback was the whole danger.
- The student list now loads your **real students** from the OGR sheet, not a
  demo set.
- Found a second, quieter bug: the "Run" button was disabled for every real
  student, because it was checking a field that only applies to demo data.
- Added a confirmation box before any real run, naming the student, so you
  can't start a real run on the wrong row by accident.
