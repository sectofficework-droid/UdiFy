### The 6 L1 bugs (the substantive engineering of this session)

Every one was found by driving the *real* portal, never guessed:

1. **Password-field ambiguity** — label matching matched more than one
   element. Fixed to select by `type="password"`.
2. **Gujarat UDISE captcha not labeled "Captcha"** — the real field carries no
   such label; detection was matching nothing.
3. **Captcha detection checked visibility, not value** — the field is visible
   but empty; needed a value check.
4. **National UDISE+ captcha label has no `for=` association** to the real
   input, so `get_by_label` could not reach it.
5. **Submit button reads "Sign In"**, not "Login", on National UDISE+.
6. (carried into 2026-09-27) `login()`'s success verification was wrong —
   found by the L3 attempt, see SESSION-2026-09-27-1.md.

## Decisions

- **Mock-first → LIVE transition**: `UDIFY_ENVIRONMENT=LIVE` on the user's
  explicit direction ("come real mode").
- **Smart App Control left entirely alone.** It blocks the unsigned
  PyInstaller `.exe`, and disabling it is a one-way system-security change —
  the user's decision alone, never this project's. Recorded, not worked
  around.
- **Inno Setup installed via winget** — with the user's explicit OK first,
  since it is a real system change.
- **Deployment path redefined**: not "copy the .exe" but
  `.venv\Scripts\pythonw.exe run_udify.py` via a Start Menu shortcut, since
  `pythonw.exe` is already trusted by the policy.
