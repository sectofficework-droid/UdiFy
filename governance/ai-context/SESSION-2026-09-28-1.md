## Decisions (who approved what)

1. User asked to "clean the project, keep only live working code, remove
   everything irrelevant especially mock mode" and stated the new working
   method: "we will directly work in live to understand how app works then
   evolve step by step with real dom analysation."
2. Before touching anything, the assistant mapped the actual scope (mock
   mode touches 20 `src/` files and ~15 of ~31 test files — not a small
   cleanup) and surfaced the real tradeoff: removing it guts the only fast,
   repeatable DOM-interaction test coverage the project had. Presented via
   AskUserQuestion.
3. User chose **"Full removal"** over the alternative (strip mock from the
   shipped app only, keep fixtures as an internal test harness) —
   confirmed explicitly, not inferred.
4. One further engineering judgment call was made without re-asking (per
   RULEBOOK.md §K2 — reasonably inferred from the already-given approval,
   not a new material decision): `MockSheetsRepository` (an in-memory
   `StudentSheetRepository` test double, unrelated to portal-DOM fixtures)
   was kept for unit tests, since it is a standard repository-pattern fake
   never used by the shipped app — distinct from the app-level MOCK/LIVE
   toggle the user was pointing at. Flagged in TODO.md in case this should
   be revisited.
